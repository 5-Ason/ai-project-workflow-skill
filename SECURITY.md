# Security Policy

## Reporting a Vulnerability

Do not open a public issue with secrets, tokens, private paths, private server addresses, or production data.

If the repository has GitHub private vulnerability reporting enabled, use that. Otherwise, open a minimal public issue that says a private security report is needed, without including sensitive details.

## Sensitive Data Policy

This repository should never contain:

- API keys, tokens, passwords, cookies, or private keys.
- Production connection strings.
- Private server IP addresses or deployment credentials.
- Private project data copied from a user repository.

## Supported Version

The `main` branch is the supported version.
