# AGENTS.md 通用结构模板

复制前先读取项目现有文档，删除不适用部分，填入真实命令和路径。

## 回复语言与协作方式

- 说明自然语言回复语言、代码和命令是否保留英文。
- 说明默认完成闭环：理解上下文、实现、验证、清理、汇报。
- 说明何时直接执行，何时必须先询问用户。

## 项目事实

- 技术栈、运行时版本、主要目录、端口、上下游服务。
- 本地启动、构建、测试、预览和部署入口。
- 当前已知限制和不能猜测的环境差异。

## 工作原则

- 修改前先读项目说明、README、相关模块文档、测试和既有实现。
- 优先复用本地 helper、组件、service、schema、脚本和代码风格。
- 改动聚焦当前请求，不做无关重构或格式化迁移。
- 字段、接口、路由、配置改名时搜索直接引用、字符串字面量、动态 import、测试、mock、文档和生成引用。

## AI 执行原则

- bug 先找根因，再修复症状。
- 连续多次修复失败时停止试错，重新评估假设或架构。
- 测试按风险决定深度，高风险路径优先补自动化检查。
- 复杂任务计划要写清目标、假设、影响文件、里程碑、验证命令和预期结果。
- 评审意见先核对项目事实，不盲从。
- 完成前用最新证据支撑结论。

## 高风险操作

列出必须先获得用户明确授权的操作，例如：

- 数据删除、重置、历史重写、force-push。
- 凭证、密钥、cookie、生产数据。
- 部署、重启生产服务、停止服务。
- 计费、购买、资源扩缩容。
- 大范围架构迁移。

## 编码规范

按项目技术栈列规则：

- 后端包结构、异常、事务、日志、数据库迁移。
- 前端路由、状态、组件、样式、API 调用。
- 跨端契约、生成代码、字段映射。
- 文件编码、注释、用户可见文案。

## 测试与验证

列出最小相关验证和广泛验证：

- 单元测试、集成测试、typecheck、lint、build。
- UI 或浏览器可见改动的页面检查。
- 脚本改动的代表性输入输出检查。
- 无法验证时最终回复必须说明原因和建议命令。

## 任务记录

说明何时写 dev-log、brief、PRD、design、decision、iteration-index，以及每次仓库改动后如何评估 project-state：只写影响后续开发判断的稳定事实，不写短期任务过程。

## Git

- 提交前检查 diff 和 status。
- 不提交密钥、生成噪音或无关格式化。
- 不默认 push 到默认分支。
- 不未经授权 force-push 或重写历史。
