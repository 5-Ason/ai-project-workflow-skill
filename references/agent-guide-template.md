# AGENTS.md 极简结构模板

复制前先读取项目现有文档，删除不适用部分，填入真实命令和路径；建议全文控制在 220 行以内。

## 工作原则与回复语言

- 自然语言回复语言，代码、命令、标识符和文件名的语言约定。
- 默认闭环：理解上下文、实现、验证、清理、汇报；改动聚焦当前请求，不做无关重构。
- 遇到 bug 先复现定位根因；连续 3 次修复失败停止试错，重新评估假设或架构。
- 测试按风险决定深度，权限、鉴权、状态机、契约与数据变更优先补自动化检查。
- 完成前必须用最新命令输出、页面检查或 diff 支撑结论；有未验证项写清原因。

## 项目事实与入口索引

- 技术栈、运行时版本、主要目录、本地端口与依赖服务。
- 核心活文档（按需查阅，不冗余堆叠）：
  - `README.md`：项目启动与常用命令
  - `docs/project-state.md`：当前系统客观快照（≤ 150 行 / 12 KB）
  - `docs/TODO.md`：唯一活跃待办（≤ 120 行 / 10 KB）
  - `docs/specs/_template.md`：大改单文件方案模板

## 开发节奏与文档维护

- **直接改（默认）**：bugfix、文案、样式、小配置、单模块小需求。直接改代码、跑验证、用语义化 Git commit 记录，不写过程日志。
- **先写方案再改（大改）**：跨模块契约、数据库改表、权限/状态机重构或多模块新功能。先在 `docs/specs/YYYY-MM-DD-<topic>.md` 写 1 份单文件方案确认后再写代码。
- 只有当长期稳定事实变化时，才覆盖更新 `docs/project-state.md`；完成 `docs/TODO.md` 事项直接删行。
- 修改核心文档或发布前运行文档防膨胀与断链检查脚本。

## 高风险操作

明确必须先获得用户授权的操作：

- 数据删除、清空、重置、历史重写、force-push、默认分支 push。
- 密钥、凭证、cookie、连接字符串与生产数据。
- 部署、重启/停止生产服务、修改服务器配置、执行生产 SQL、计费或扩缩容。

## 编码与契约关键规则

按项目实际技术栈列出不可违背的红线（长示例拆到按需查阅的手册中）：

- 后端接口规范、异常码、事务、日志与数据库迁移目录。
- 前端路由、状态管理、mock 隔离与样式规范。
- 跨端契约生成与检查命令。
- 统一文件编码（如 `UTF-8 without BOM`）。

## 验证与 Git

- 列出后端、前端、契约、文档等最小常用验证命令。
- 提交前检查 `git diff --stat` 与 `git status --short`；不提交密钥、本地路径或构建噪音；使用清晰语义化 commit 前缀（`feat:`、`fix:`、`docs:`、`refactor:`、`test:`、`chore:`）。
