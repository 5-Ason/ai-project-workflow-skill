# 极简项目记忆与防膨胀护栏

## 目标

只保留“能让下一次 AI 任务立刻接上上下文且不误踩坑”的最少信息，用硬体积上限和自动化脚本防止文档重新膨胀。

## 3 个活文档的唯一边界

### 1. `AGENTS.md`（稳定规则）
- 只放每次任务都必须遵守的规则：回复语言、编码红线、技术栈与关键约定、高风险授权边界、常用验证命令、Git 规范。
- 长代码示例、SQL 模板或部署操作手册放到独立参考文档，按需查阅，不塞进 `AGENTS.md`。

### 2. `docs/project-state.md`（当前系统快照）
- 回答一个问题：**“这个系统现在真实长什么样，有哪些不能踩的坑？”**
- 推荐固定 4 个小节：环境与部署现状 / 核心模块现状 / 关键技术边界 / 未解决的已知限制。
- **必须覆盖式更新**：旧事实过时直接改写或删除，禁止按日期不断追加“某天修完什么、跑过多少条测试”。
- **硬红线**：建议 ≤ 150 行且 ≤ 12 KB。

### 3. `docs/TODO.md`（唯一活跃待办）
- 回答一个问题：**“现在还有哪些未完成的工作和已知未修的坑？”**
- 仅保留 3 组：`进行中` / `待排查与待做` / `技术债（低频）`。
- **做完直接删行**，不在文件里保留“已完成列表”（需要追溯看 Git log）。
- **硬红线**：建议 ≤ 120 行且 ≤ 10 KB。

## 单文件大改方案模板（`docs/specs/_template.md`）

大改时只建 1 个文件 `docs/specs/YYYY-MM-DD-<topic>.md`，合并需求、设计与验收：

```markdown
# <功能或重构标题>

- 日期：YYYY-MM-DD
- 状态：draft / confirmed / done
- 影响范围：<模块 / 端 / 数据库 / 契约>

## 1. 目标与非目标

- **目标**：一句话说清解决什么问题、达到什么效果。
- **不做什么**：明确排除范围，避免蔓延。

## 2. 核心设计

- **数据与迁移**：是否涉及表结构变更及迁移脚本位置。
- **接口与契约**：新增/变更的接口、核心字段与权限边界。
- **边界与失败处理**：并发、异常、回退或兼容策略。

## 3. 验证清单

- [ ] 单元测试 / 核心路径检查
- [ ] 构建 / 契约 / 冒烟检查
- [ ] 若改变了系统稳定事实，已覆盖更新 `docs/project-state.md`
```

## 配套轻量校验脚本建议

只靠文档约定约束不了文档膨胀。建议在项目中放一个极简脚本（如 `scripts/check-doc-memory.mjs`），接入发版预检或 CI，只做 3 件事：

1. 检查核心入口文件存在（`AGENTS.md`、`README.md`、`docs/project-state.md`、`docs/TODO.md`）。
2. 检查硬体积与行数红线（超标直接以非零退出码失败），同时可顺手检查 UTF-8 无 BOM。
3. 扫描活文档中的 Markdown 相对路径链接，确保无断链（跳过代码块与外部 URL，不校验历史归档目录）。

## 收尾检查清单

每次产生仓库改动后、最终回复前核对：

1. 查看 `git diff --stat` 和 `git status --short`，确认改动聚焦且无多余噪音文件。
2. 运行与本次改动相关的最小必要验证命令并核对最新输出。
3. 若改变了长期系统事实，已覆盖更新 `docs/project-state.md`；若完成了待办，已从 `docs/TODO.md` 删除对应行。
4. 涉及活文档或发版前，已运行文档防膨胀与断链检查脚本。
5. 最终回复写清改了什么、验证了什么、未验证项及原因。
